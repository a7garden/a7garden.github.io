1. 무엇이 다른가

Google Calendar는 미래의 약속을 잡는 도구이고, 전통적 투두 앱은 시간 없는 마감일이다. oxiline은 그 둘이 답하지 못하는 질문에 답한다 — "지금 뭘 해야 하지?" 하루 종일 여러 번 묻는 그 순간, 단축키 한 번으로 2초 안에 답이 떠오르고 사라진다.

관점전통 캘린더전통 투두OxiLine
시간의 성격정적 좌표시간 없음 (마감일)흐름 — 지금이 어디인지 항상 화면에 존재
반복 단위이벤트 반복 규칙반복 없음이 기본하루의 구조 자체가 반복
접근 방식앱을 열어서 본다앱을 열어서 본다앱을 열지 않고도 단축키로 2초 확인

2. 핵심 기능 5가지

  1. 오늘 타임라인: 세로 시간축 위에 루틴/할일이 구간(block)으로 배치된 하루 뷰. 실시간으로 흐르는 "지금 선(Now Line)"이 화면을 가로지른다.
  2. 루틴: 요일 반복 규칙을 가진 시간 구간 템플릿. 매일 다시 만들 필요 없이 하루의 뼈대를 구성.
  3. 날짜별 할일 / 백로그: 특정 날짜에 고정된 일회성 항목과, 날짜 없는 미정 할일(Inbox)을 모두 지원.
  4. 전역 단축키 플로팅 HUD: 어떤 앱을 쓰고 있든 단축키 한 번으로 "지금 뭘 해야 하지?"의 답이 2초간 떠 있다 사라진다.
  5. CLI + 에이전트 연동: oxiline CLI로 사람도, AI 에이전트도 동일한 데이터를 읽고 쓴다.

3. oxi 생태계 내 위치

oxiline은 다음 원칙을 oxi 생태계의 다른 작품과 공유한다.

  • Rust 우선주의: 비즈니스 로직·데이터 검증·영속성은 전부 Rust 코어. UI(React)는 얇은 표현 계층.
  • CLI가 1급 시민: GUI가 CLI의 래퍼가 아니라, CLI와 GUI가 동일한 코어 라이브러리를 공유하는 두 개의 얇은 클라이언트.
  • 로컬 퍼스트: 클라우드 동기화·계정·서버는 v1 범위 밖. 모든 데이터는 로컬 SQLite 파일 하나.
  • 미니멀리즘: 기능을 최대한 쌓지 않는다. "지금 흐름을 본다"는 한 가지에 집중.

4. 데이터 모델 — 가상 occurrence + 지연 구체화

"루틴은 반복되지만, 특정 날짜의 사정은 다를 수 있다"는 요구를 별도 예외 테이블 없이 tasks 테이블 하나로 통합.

routine_blocks

반복 구간 템플릿 · weekday_mask(bit0=월..bit6=일) · effective_from/until · color_override(OKLCH)

routine_groups

루틴 묶음 (예: "평일 아침", "주말") · 그룹 전체 on/off

tasks

수동 + 구체화된 occurrence. source='manual'/'routine', date=NULL이면 백로그. unique index로 중복 occurrence 방지

categories

색상 태그 · OKLCH H 값 · is_builtin 시드 표시

모든 시간은 로컬 타임존 기준 분 단위 정수로 저장한다 (UTC 변환 비용 감수 안 함).

6. v1에서 의도적으로 하지 않는 것

  • 팀 협업·공유·멀티유저 — 개인용 로컬 앱
  • 클라우드 동기화·계정 로그인 — 로컬 SQLite가 유일한 진실
  • Windows/Linux 지원 — macOS 단일 타겟
  • 복잡한 프로젝트 관리(서브태스크 트리·칸반·간트)
  • 습관 스트릭·게이미피케이션 점수 시스템
  • AI 자동 일정 생성 — 대신 CLI를 통해 에이전트가 사용

7. 설계 문서

8개 문서가 전체 설계를 담고 있다 — 제품 철학 → 리서치 → 데이터 모델 → 아키텍처 → CLI → 디자인 시스템 → 화면 → 로드맵. 원샷 프롬프트로 구현 가능한 수준으로 스키마·명령어·토큰 값을 명시했다.
